### Changes

- Hostile review fixes (council pass 3):
  - Leaving a message you are writing now asks "Discard this message?" with
    Save draft, Discard and Keep writing: clicking another message, a folder,
    Contacts or Settings, starting a new message, Reply or Forward from a
    popped-out message, a notification, and closing the compose pane or its
    own window. An empty message closes without asking. Save draft leaves
    only once the draft is saved and nothing changed meanwhile, an address
    still being typed included. Before, the message was thrown away silently.
  - A contact's PGP key is checked when you save the contact, with the
    server's rules: one public key, not revoked or expired, for one of the
    contact's addresses. A key that fails, or that cannot be checked because
    GnuPG is missing, is refused with the reason and the contact's name. A
    contact too large to sync is refused too. Before, either stopped every
    later contact sync. If the server still refuses a key, the error names
    the contact. Contact changes are sent in batches the server accepts.
  - Pairing a different account, including after "Remove pairing", always
    removes the previous account's cached mail, also when it happened during
    a session kept in memory (the next normal launch removes it). If
    contacts are on this device, KyPost asks "Bring your N contacts into
    <server>?" and syncs none of them until you answer. Bring them adds them
    to the new account as new contacts (without the old server's photos);
    Remove them deletes them from this device. "Remove pairing" now asks
    first and offers "Also remove this device's contacts", off by default,
    with a warning when changes have not synced.
  - A plain send first checks how the account protects mail. If that cannot
    be checked, or the account encrypts its mail on the client (with or
    without GnuPG on this computer), nothing is sent and you are told why.
    Before, a failed check sent the message unencrypted.
  - An encrypted send whose Bcc delivery may have failed says so; a Sent
    copy that could not be filed is not reported as a Bcc problem.
  - An encrypted reply is now linked to the message it answers, like a plain
    one. If the server cannot link it, nothing is sent and the next Send
    goes out as a new conversation.
  - Pressing Send (or Save draft) twice quickly no longer sends the message
    twice.
  - An attachment over the 25 MB limit is refused before it is read, rather
    than read whole into memory first.
  - When the server's certificate authority changes, the dialog sends you to
    pair again with a new link from your KyPost web page. A pairing link for
    the account already paired says "This server's certificate changed since
    you paired" unless KyPost has checked that the server still presents the
    key it pinned; when it has, the pairing stays pinned to that key.
  - When your push service gives KyPost a new address, KyPost now updates
    the server with this device's own credentials. Before, it re-sent the
    one-time pairing token, which the server always refused, and
    notifications stopped. A server without the update still shows the
    "pair again" banner.
  - Waiting for a new pairing's approval survives the app lock. Before,
    switching to the browser to approve locked the app and cancelled the
    wait, so pairing with the app lock on could not finish.
  - The first refresh of a folder after launch replaces messages below the
    newest 50 even if the device was unpaired at launch.
  - Attachment names in the reader lose the same invisible characters as
    saved files. A download that finishes after the app locks now says it
    was not saved.

### Upgrade impact

- Contacts created on this device by 0.6.0 or earlier, and not yet synced,
  are still sent without their own identifier on their first sync.
- A server without `POST /api/notifications/native/refresh` keeps the
  previous behaviour: after a push address change, pair again with a new link.
